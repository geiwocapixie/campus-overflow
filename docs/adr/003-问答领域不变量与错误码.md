# ADR-003：问答领域的不变量校验位置与错误码分段

**状态**：已接受 ｜ **驱动特征**：可测试性、可演进性 ｜ **相关场景**：S2 Q&A 核心

## 背景

`co-qa-domain` 的 18 个单元测试是 S2 的需求说明书：提问、编辑、采纳、软删除、回答、投票、评论、标签数量与正文长度都有明确断言。
如果把这些校验放在应用层或控制器，同一规则会在三个地方重复，且领域测试无法覆盖；
接口层还需要一套稳定的错误码，否则前端只能靠文案判断失败原因。

## 决策

1. **不变量收敛在聚合根内部**：`Question`、`Answer`、`Vote`、`Comment`、`Tags`、`MarkdownBody` 各自在命令方法里完成校验，
   应用层只负责加载聚合、开事务与发布事件，不重复业务判断。
2. **异常三分类，由接口层统一映射**：`ForbiddenException`（403）、`ConflictException`（409）、`BusinessRuleException`（422），
   领域层只抛这三类，不感知 HTTP。
3. **错误码按语义分段**：`QA-1001~1018` 为规则校验，`QA-2002~2003` 为状态冲突，`QA-3001~3004` 为权限。
   新增规则时在同一段内递增，不复用已发布码。
4. **采纳入口唯一**：`Question.accept` 校验"回答属于该问题、回答未删除、问题未重复采纳"；
   "采纳后不再接受新回答"由 `Question.ensureOpenForAnswers` 承担，供应用层在提交回答前调用，
   `Answer.submit` 本身不查问题状态，避免同一规则两处实现。
5. **软删除只写 `deletedAt`**：不物理删除；对已删除对象的任何操作统一抛 `QA-1008`。
6. **投票值取 `-1 / 0 / 1`**：`0` 表示撤销，重复提交同值幂等；不允许给自己的内容投票（`QA-1015`）。
7. **字段边界固定**：标题 10–150 字、问题正文 1–30000 字、评论 1–600 字、标签 1–5 个。

## 后果

- 正面：领域测试可直接驱动实现，规则改动只改一处；错误码稳定，前端与验收用例可断言。
- 负面：聚合方法需要携带操作者身份与必要的上下文参数（如课程角色），签名略长；
  错误码表需要人工维护，新增规则时若忘记登记会出现空档。

## 被否决的替代方案

- 校验放在应用层：领域对象退化为数据容器，测试只能覆盖服务编排，规则改动点分散。
- 用全局错误码枚举：教学阶段规模小，枚举会引入与共享内核的额外耦合，且不利于按上下文分段演进。
- 用 boolean/Optional 返回代替异常：调用方容易忽略失败分支，接口层也难以区分 403/409/422。
