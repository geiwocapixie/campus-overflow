# CampusOverflow Product Backlog v1.0

> 维护人：杨杰（Product Owner）　创建日期：2026-10-26　最后更新：2026-10-26
> 需求来源：`docs/research/interviews/interview-01~03.md`（3 份真实用户访谈 U1–U3）

## 1. 产品目标

让本校学生在遇到课程问题时，能在 1 分钟内把问题描述清楚、在 24 小时内拿到可验证的答案，
并且这些问答能沉淀成可搜索、可复用的课程知识库。

首版聚焦"能问 → 能看 → 能答"的最小闭环，把声誉、悬赏、排行榜等激励功能排在闭环打通之后。

## 2. 优先级方法

- **MoSCoW**：Must（本 Sprint 不做产品不成立）/ Should（重要但可延后）/ Could（锦上添花）/ Won't（本期不做）。
- **价值 / 成本二维矩阵**：先做"高价值 + 低成本"，高价值高成本项按 Sprint 容量逐条进入，低价值高成本项不排期。

| 象限 | 故事 |
| --- | --- |
| 高价值 · 低成本（先做） | US-01、US-02、US-03、US-05、US-16 |
| 高价值 · 高成本（按容量分批） | US-06、US-07、US-09、US-12 |
| 低价值 · 低成本（顺手做） | US-10、US-13 |
| 低价值 · 高成本（暂缓） | US-14、US-15 |

## 4. MVP 切片（Walking Skeleton）

**US-01 → US-02 → US-03 → US-05 → US-06 → US-07**

一条完整的用户旅程：新用户注册 → 登录 → 看到问题列表 → 打开详情 → 发布自己的问题 → 收到第一条回答。
这条链路打通后，产品即可在 Sprint Review 上被真实演示；搜索、投票、采纳、声誉等能力都在此骨架上增量叠加。
